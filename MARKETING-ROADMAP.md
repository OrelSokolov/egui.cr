# Marketing Roadmap — целевые сообщества и демонстрационные приложения

egui.cr — уже рабочий кроссплатформенный desktop-UI на Crystal (Linux /
macOS / Windows, сборки в `builds/`). Ближайшая цель: показать фреймворк
большим активным сообществам, где он снимает реальную боль, и дать людям
возможность писать на нём простые, но полезные инструменты в ближайшие
месяцы.

Критерии выбора ниши:

- **Большое активное сообщество** (форумы, Reddit, Discord, GitHub — где
  есть кому увидеть демку и подхватить идею).
- **Реальная неудовлетворённость существующими инструментами**, а не
  «ещё один красивый UI».
- **Живое железо / ОС как источник данных** — подчёркивает сильную
  сторону стека: Crystal ↔ C-расширения (`pty_shim`, `nanosvg_shim`,
  `sokol_shim`) ↔ реальное устройство.
- **MVP силами одного человека за недели**, а не годы.

## Почему egui.cr подходит таким инструментам

- Immediate mode = перерисовка каждый кадр — буквально нативный режим
  работы для осциллографов, мониторов и графиков живых данных.
- Прецеденты уже в репо: `system_monitor` (живые данные из ОС + графики),
  `terminal` (неблокирующий I/O через pty_shim). Сериал-порт проще PTY.
- Один статический бинарник, без рантаймов и установщиков — норма для
 _embedded_-сообщества, привыкшего к «скачал и запустил».

## Ниша 1 — Arduino / embedded: Serial Monitor + Plotter (флагман)

Стоковый Serial Plotter в Arduino IDE — давно объект ненависти: уродливый,
каналы без индивидуального масштаба, нет паузы, нет экспорта. Аудитория —
миллионы пользователей, боль документирована.

MVP (порядка выходных):

1. Open port + baud selector; serial через termios прямо из Crystal
   (`lib C`), отдельный shim не нужен; на Windows — Win32 API (вот где
   появится настоящий C-shim, что тоже плюс к нарративу).
2. Line-протокол (`ax,ay,az\n`), скроллящийся график каналов: пауза,
   autoscale, per-channel scale.
3. Отправка команд обратно + raw/hex вид на базе терминал-виджета.
4. Скетч на ~20 строк на стороне Ардуино.

Наращивание: CSV export, триггеры как в осциллографе, сохранение сессий.

Операционные риски: права на `/dev/ttyUSB0` (группа `dialout` — нужен
вменяемый error, не падение), hotplug-детект (udev) — полировка, не MVP.

## Ниша 2 — 3D-печать: serial-консоль к Marlin/Klipper

Сообщество огромно и мучается с OctoPrint (Python, веб, Heavy).
Terminal-виджет уже готов — остаётся парсер G-code ответов и удобный
мониторинг печати (температуры как графики — тот же код, что в нише 1).
Серийный слой полностью переиспользуется из ниши 1.

## Ниша 3 — QMK / механические клавиатуры

UI для прошивки и конфигурации раскладок. Тут C-расширения нужны по
честному (hidapi) — сильная демонстрация тезиса «Crystal ↔ C ↔ железо».
Аудитория — r/MechanicalKeyboards, очень активная и любит инструменты.

## Ниша 4 — Raspberry Pi / IoT: GPIO-дашборд

Панель состояния и управления пинами поверх serial/MQTT/websocket.
Меньше боли у существующих инструментов, но лёгкий вход и хороший
материал для туториалов «напиши свой инструмент за вечер».

## Приоритеты

| # | Ниша | Продукт | Почему таким порядком |
|---|---|---|---|
| 1 | Arduino/embedded | Serial Monitor + Plotter | MVP за выходные; максимум боли; serial-слой — фундамент для всего остального |
| 2 | 3D-печать | Marlin/Klipper консоль | переиспользует нишу 1 + готовый terminal-виджет |
| 3 | QMK | флешер/конфигуратор | настоящий C-shim (hidapi); отдельный трек |
| 4 | RPi/IoT | GPIO-дашборд | туториальный контент, привлечение контрибьюторов |

## Что это даёт фреймворку

Каждая ниша — это одновременно и демка, и движок доработок ядра
(см. `SHARDS-ROADMAP.md`: focus events для паузы рендера, tray для
фоновых мониторов). Инструмент с пользователями — лучший драйвер
развития фреймворка.
