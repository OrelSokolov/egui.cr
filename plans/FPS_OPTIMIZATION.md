# FPS: двигательная оптимизация — retained paint под immediate API

> Цель: сделать «быстрее браузера» свойством архитектуры, а не
> результатом ручного тюнинга каждого приложения. Записано
> 2026-11-11, после аудита `FutureOptimizations.md` (бенчи, горячие
> места), `loop_redesign.md` (FramePacket уже сделан),
> `NativeHTML.md` (§6 кодоген, §10 non-goals), `memory_optimization.md`.

## 0. Диагноз

Браузер быстр не интеллектом, а устройством: **retained + damage
tracking + кэш растеризации** — пока ничего не меняется, он не делает
ничего; при hover перестраивается один слой. egui.cr — immediate:
каждый кадр перестраивает всё дерево, и скорость сегодня достигается
точечными opt-in'ами на уровне приложения (`ScrollArea virtual:`,
`measure_cached`, ручной тюнинг html_gallery). Поэтому «не везде»:
быстрый путь — исключение, а не дефолт.

Мера разрыва: html_gallery — база ~31 мс/кадр dev → 1.82 мс после
ручных оптимизаций (`FutureOptimizations.md`), т.е. ~17× снято руками.
Release p50 0.28 мс показывает, что потолок не архитектурный —
стационарный кадр можно сделать почти бесплатным по умолчанию.

Ключевая идея, связывающая всё: **API остаётся immediate, вывод кадра
становится memoized**. Это НЕ VDOM и НЕ retained DOM из non-goals
(`NativeHTML.md` §10) — приложение как писало `update(ctx)` каждый
кадр, так и пишет. Меняется только то, что движок делает с результатом.

## 1. Retained paint: кэш вывода поддерева по ключу

Кадр — чистая функция от (дерево, стили, input state). Для каждого
виджета кэшировать layout + paint-команды по ключу
`(id, hash стиля, hash контента, constraints)`. Ключ не изменился —
переиспользуем прошлокадровые команды как есть (с новой
clip-трансформацией).

- Требование: красить в **per-widget бакеты**, а не в один общий
  список (слои уже есть в Painter — обобщить до id-поддеревьев).
- Эффект: стационарный кадр из «`Egui::Label` 76µs × 48 + `Button`
  3 мс self + панель 2.6 мс» (разрез `FutureOptimizations.md`)
  → почти ноль; hover меняет ключ двух виджетов, остальные сотни
  отдаются из кэша.
- Инвалидация тривиальна для нашего скоупа: нет JS, который может
  переломать DOM в любой момент — монетизируем преимущество
  подмножества.

## 2. Damage tracking + частичный презент

Раз команды кэшированы по виджетам (§1), появляется dirty-регион:
пересобрать и переэмитить только изменившиеся бакеты, остальное —
replay. На render-потоке уже есть `replay_last` (`loop_redesign.md`
§8) — расширить с «все команды не изменились» до «изменились эти».

- Hit-test по retained-геометрии из Memory (rects уже пишутся):
  движение курсора над 1000 иконок перестаёт быть полноценной
  пересборкой кадра — перестройка только если hover-состояние
  реально переключилось, и тогда только два виджета.

## 3. Нулевая аллокация в стационарном кадре

Текущие источники (замеры в `FutureOptimizations.md`):

| что | цена |
|---|---|
| `effective_style` — новый `Style` на кнопку на кадр (merge каскада) | 193 аллокации/кадр |
| `Memory#interact` — шесть хэшей на виджет (`@widget_rects/@widget_senses/…` + seen/used) | ~1200 хэш-операций/кадр |
| `Icon.cached` — строковый ключ `"lucide/arrow-up/255/255/255"` | ~1.25 мс/кадр (уже в плане там же) |
| `Svg#paint` raster-lookup — хэш всего source (~700 байт) на иконку | ~0.8 мс/кадр (уже в плане) |

Направления:

- **Frame arena**: bump-аллокатор на кадр, сброс в `end_frame`.
  Не ждать `--gc=none` из `crystal_arenas_plan.md` — арена на уровне
  движка делается сейчас, без изменений языка.
- **Слоты вместо хэшей**: id → integer slot один раз, per-frame
  данные в параллельных массивах (SoA). Шесть `Hash`-обращений →
  один индекс.
- **Style sharing** (как Servo): виджеты с одинаковым
  `(классы, state, родительский стиль)` делят один разрешённый
  стиль. Каскад-merge один раз на класс-набор, не на кнопку.

## 4. Кэш тесселяции + SDF/instancing — убрать ~30k FFI-вызовов/кадр

Каждый rounded rect ≈ 24 квада, текст — квад на глиф; sgl-эмиссия —
узкое место после CPU-части (прогноз в `FutureOptimizations.md`).
Усиливается §1: раз paint-команды кэшированы по виджетам, меш
кэшируется тем же ключом — переэмитить только грязные бакеты.

- **SDF-квад** для rounded rect: 1 квад вместо 24 (прецеденты —
  sdf-эксперименты в tmp/, `sdf_circle_probe.cr` и серии скриншотов).
- **Instanced draw** для текста: квад на глиф, UV в атлас, один
  draw call. Место, где GL-пайплайн честно обгоняет Skia браузера
  на UI-примитивах.

## 5. Инкрементальный layout

Кэш галлеев уже сделан (`spec/layout_cache_budget_spec.cr`, MRU →
байтовый бюджет). Тот же принцип на box-дерево:

- memo по `(content-hash, constraints)`;
- инвалидация снизу вверх: изменилась ширина узла → пересобрать
  родителя, братья — из кэша;
- полный перемер — только на ресайз (как сегодня в `virtual:`
  scroll, но автоматически для всего).

## 6. Компиляция каскада — то, что браузер не может в принципе

exml-кодоген (`NativeHTML.md` §6) планируется как «литералы
`Array(Node)`». Расширить: для статических class-path **резолвить
каскад на этапе кодогена**, emit плоские resolved-структуры. В
рантайме — только delta за `:hover`/`active`.

- Селекторы → битсеты; класс-набор → perfect-hash индекс стиля.
- Браузер платит за selector matching каждый кадр; мы платим один
  раз на билде. Самый честный ответ на вопрос «чем компилируемость
  даёт скорость».

## 7. Мелочи (дёшево, снять константы)

| что | фикс | эффект |
|---|---|---|
| `Painter#commands_in_layer_order` O(слои×команды) | один проход, бакеты по z, конкатенация | ~0.3 мс |
| `Icon.cached` строковый ключ | tuple-ключ `{provider, name, tint}` | ~0.8 мс, ноль аллокаций |
| `Svg` raster-lookup | ленивый `@raster_key` — хэш source один раз в жизни инстанса | ~0.7 мс |

(§7 = пункты 2–4 текущего плана в `FutureOptimizations.md`, здесь
сведены для полноты.)

### Этап 0 — сделан 2026-11-11

- `Icon.cached` — tuple-ключ `{provider, name, tint}`; A/B
  (lucide, 3+3 DEV-прогона): 8.5–8.9 → 7.0–7.6 µs/call (−0.3 мс/кадр),
  минус строка-аллокация на иконку/кадр.
- `Svg` raster-lookup — ленивый `@raster_key : {UInt64, Color32}`
  (hash source один раз в жизни инстанса, коллизия 2⁻⁶⁴ принята);
  `Svg#paint` self 20.9–21.9 → 19.5–20.3 µs/call (−0.15 мс/кадр).
- `Painter#commands_in_layer_order` — counting sort по z ∈ [0, 100]
  (диапазон гарантирован clamp'ом в обоих сеттерах слоя), стабильный,
  scratch-буферы переиспользуются; O(n + z) вместо O(слои × команды).
  На lucide спан шумный (доминирует копирование union-команд) —
  выигрыш в масштабируемости на многослойных кадрах.
- `Egui::FrameArena` (`src/egui/frame_arena.cr`) — bump-аллокатор на
  кадр: `#bytes`/`#slice(T)` 8-байтно выровнены, геометрический
  рост до high-water, `#reset` в `Context#end_frame`, телеметрия
  `#bytes_used`. Только POD-скретч кадра; команда-лист `end_frame`
  не должен ссылаться на память арены. Фундамент этапа 1 (слоты
  Memory), потребителей в 0 нет — спека `spec/frame_arena_spec.cr`.
- Итог по кадру lucide (p50, pre-FFI): ~15.3–16.4 → ~14.4–14.7 мс
  (−1 мс/кадр суммарно со всеми тремя фиксами).
- Спеки: 1231 пример, зелёные.

### Этап 1 (часть 1: слоты Memory) — сделан 2026-11-11

`Memory` переведён с восьми per-frame Hash/Set на id→slot
(персистентный `Hash(Id, Int32)`) + параллельные SoA-массивы:

- `#interact` — **одна** хэш-операция (id→slot) вместо восьми;
  регистрация порядка (`@cur_order`) сохраняет порядок регистрации
  (тай-брейки hit-test «последний на равном z выигрывает» и позиционные
  чтения `widget_rects.values` в спеках);
- ротация кадра — swap пар массивов + инкремент поколения `@geo_gen`:
  ноль копирования, ноль очистки (валидность = сравнение штампа с
  абсолютным поколением), ноль аллокаций;
- used-set пересобирается в `end_frame` из штампов `@cur_used`
  (interact ИЛИ `use_id`); мёртвые слоты освобождаются в free-list,
  компакция при >50% дыр (id-churn виртуальных списков не течёт);
- публичные хэш-геттеры (`widget_rects`, `prev_widget_rects`,
  `prev_widget_senses`, `prev_widget_layers`) стали ленивыми view —
  перестраиваются при первом чтении после записи (`@geo_version`);
  кадр за них не платит, спеки/inspector/capybara не изменились;
- починено по ходу: `register_scroll_area` писал id прямо в used-set
  мимо слотов — `end_frame`-пересборка его стирала (контент-ячейка
  scroll-областей вылетала из IdTypeMap → offset навсегда 0;
  11 scroll-спеков ловили это).

A/B (`bin/lucide_bench`, DEV, 3+ прогона; после этапа 0 → после
слотов): **кадр p50 14.4–14.7 → 7.6–8.3 мс** (≈ −47%), begin_frame
0.25→0.07 мс. Каскад по всем спанам: Button self 29.8 мкс (было 57.5
до этапов, 38 после 0), Label 6.5 (14.7), Svg#paint 10.6 (19.6),
Icon.cached 3.9 (7.0), Memory#end_frame self 47.7 мкс/кадр.
Полная таблица: `tmp/stage1_memory_bench.txt`. Спеки: 1250 зелёные.

Осталось в этапе 1: ~~style sharing~~ — ✅ сделано 2026-11-11 (ниже).

### Этап 1 (часть 2: style sharing) — сделан 2026-11-11

Finer-спаны внутрь `Button#ui` (`#style`/`#measure`/`#interact`/`#state`,
нулевая цена вне бенчмарка) подтвердили диагноз §3: каскад — 62 мс
суммарно (`Button#style` 3.4 + `Button#state` 3.0 мкс/вызов × 2 слоя),
`interact` после слотов — 0.6 мкс, `measure` — 0.1 мкс (кэш ширин).
Главный аллокатор — `StyleVars#apply_over` → `base.clone` на кнопку
на кадр (обе `resolve`-функции и так возвращают ОБЩИЕ кэшированные
бэги).

Реализация — два кэша в `StyleSheet` (очищаются вместе с `@resolved`
во всех пяти местах: rule-изменения, media-флипы):

- `#shared_apply(bag, base)` — identity-ключ `{StyleVars, Style}`:
  resolve-бэги и базовые стили — контрактно immutable shared-объекты,
  ключи держатся сильно (GC не переиспользует адрес кэшированного
  ключа) → один merged Style на класс-набор;
- `WidgetStyle#merge_over_shared` — value-ключ (для WidgetStyle
  написаны `#==`/`#hash` по 9 полям): immediate-виджеты — свежие
  объекты каждый кадр, identity там не попадает;
- `effective_style` гоняет все три слоя через кэши; счётчики
  `style.share.hit` / `style.share.inline.hit` в телеметрии.

A/B lucide: `Button#style` 3.4 → **1.9 мкс/вызов** (−44%),
hit-rate 4824/4825 и 4799/4800; кадр p50 ~8.0–8.2 мс (в пределах
шума этапа 1 ч.1 — с учётом добавленных спанов-инструментации это
«больше, чем окупило себя»); аллокаций каскада в стационаре ≈ 4/кадр
вместо ~400. html_bench: 1.09 мс/кадр p50, без регрессий.
Спеки: 1250 зелёные.

**Этап 1 закрыт полностью.** Итог по lucide за два этапа:
кадр p50 15.0 → 8.0 мс (−47%), у Engine Button self 57.5 → 24.5 мкс.
Следующий — этап 2 (per-widget paint-бакеты + кэш по ключу).

### Этап 2 (часть 1: retained paint для Button/Label) — сделан 2026-11-11

API остаётся immediate, вывод кадра memoized: `Ui#add`/`#add_sized`
при наличии у виджета ключа реплеят записанный paint вместо запуска
`#ui` (hit: allocate + interact + переэмиссия команд с recorded z;
miss: прогон под захватом). Файлы: `src/egui/paint_cache.cr` (Entry +
кэш + replay), хуки в `ui.cr`, ключи в `button.cr`/`label.cr`,
`Memory#interaction_state` (детерминированное зеркало hover/active
вердикта ДО регистрации — вход ключа), `Painter#take_bucket`/
`#replay_add`/`xform_epoch`.

Ключевые решения:
- ключ = (контент-поля виджета, identity resolve-бэгов стилей,
  identity базового Style, constraints, доступная ширина) → UInt64;
  Ui добавляет id виджета, focus-флаг, font_scale, ppp. Инвалидация
  стилей НЕЯВНАЯ: смена правила/темы выдаёт свежие объекты → miss;
  тема чистит кэш явно;
- **id-стабильность**: entry хранит, сколько child-id виджет
  потребил; реплей переминчивает тот же спан — id братьев не
  съезжают (баг двух одинаковых `<vue_counter>` ловился спекой);
- реплей позиционен: команды абсолютны, сдвиг виджета →
  translate-only TransformFrame + пере-клип (пересечение сдвинутого
  записанного клипа с амбиентным);
- гейты: Flex measure-проход, любые живые transition/appear-анимации
  (глобально — ячейки transitions живут под salted id, пер-виджетно
  их не видно; одна анимация ставит кэш на паузу — осознанная
  грубость), xform-эпоха захвата, Mesh3DCmd (данные — указатель
  виджета), selectable/preset Label;
- свежие-в-кадр виджеты: Label ключуется по VALUE (text+форматting),
  не по object_id — immediate-приложения создают Label каждый кадр;
- бюджет 100k команд, clear-on-overflow, stale-выселение ≥3 кадров.

A/B lucide (stationary hover): **hit 9240 / miss 385 (96%)**, кадр
p50 **8.0 → 4.59 мс**; Button/Label/Svg#paint вызываются только на
захвате (193/217/193 вызовов суммарно против 4825). Спеки:
1257 зелёные (включая 5 новых spec/paint_cache_spec.cr: реплей =
тот же вывод, content-change → miss, клик/hover на кэшированном,
theme-swap → clear, сдвиг позиции → транслированный paint).

Итог трёх этапов на lucide: **15.0 → 4.59 мс p50 (−69%)**, ≈218 fps
CPU ceiling pre-FFI. Осталось в этапе 2: opt-in остальных виджетов
(checkbox/toggle/slider/…), пер-id гейт анимаций, и этап 3
(dirty-регион + частичный replay на render-потоке).

## Критерий готовности

1. **Дефолтный быстрый путь**: `bin/html_gallery` БЕЗ единого
   ручного opt-in (без `virtual:`, без `measure_cached`) показывает
   те же ~1–2 мс dev p50, что сегодня даёт ручной тюнинг
   (`FutureOptimizations.md`): быстрый путь — свойство движка.
2. **Hover-кадр**: движение курсора по статичному экрану иконок
   (lucide-бенч) — перестройка только затронутых виджетов; счётчик
   rebuilt-widgets/кадр в телеметрии.
3. **Стационарный кадр**: ноль аллокаций в установившемся режиме
   (счётчик аллокаций между `begin_frame`/`end_frame`).
4. **Oracle по времени**: сравнение с браузером не только по
   скриншотам (oracle/ уже есть), но и по времени кадра — иначе
   «быстрее браузера» нечем подтвердить.
5. Спеки `spec/*_spec.cr` зелёные на каждом этапе; меряем в DEV
   (политика `FutureOptimizations.md` — release не смотрим никогда).
