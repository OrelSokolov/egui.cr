# FPS: двигательная оптимизация — retained paint под immediate API

> Цель: сделать «быстрее браузера» свойством архитектуры, а не
> результатом ручного тюнинга каждого приложения. Записано
> 2026-11-11, после аудита `FutureOptimizations.md` (бенчи, горячие
> места), `loop_redesign.md` (FramePacket уже сделан),
> `NativeHTML.md` (§6 кодоген, §10 non-goals), `memory_optimization.md`.

## 0. Диагноз

Браузер быстр не интеллектом, а устройством: **retained + damage
tracking + кэш растеризации** — пока ничего не меняется, он не делает
ничего; при hover перестраивается один слой. egui.cr — immediate:
каждый кадр перестраивает всё дерево, и скорость сегодня достигается
точечными opt-in'ами на уровне приложения (`ScrollArea virtual:`,
`measure_cached`, ручной тюнинг html_gallery). Поэтому «не везде»:
быстрый путь — исключение, а не дефолт.

Мера разрыва: html_gallery — база ~31 мс/кадр dev → 1.82 мс после
ручных оптимизаций (`FutureOptimizations.md`), т.е. ~17× снято руками.
Release p50 0.28 мс показывает, что потолок не архитектурный —
стационарный кадр можно сделать почти бесплатным по умолчанию.

Ключевая идея, связывающая всё: **API остаётся immediate, вывод кадра
становится memoized**. Это НЕ VDOM и НЕ retained DOM из non-goals
(`NativeHTML.md` §10) — приложение как писало `update(ctx)` каждый
кадр, так и пишет. Меняется только то, что движок делает с результатом.

## 1. Retained paint: кэш вывода поддерева по ключу

Кадр — чистая функция от (дерево, стили, input state). Для каждого
виджета кэшировать layout + paint-команды по ключу
`(id, hash стиля, hash контента, constraints)`. Ключ не изменился —
переиспользуем прошлокадровые команды как есть (с новой
clip-трансформацией).

- Требование: красить в **per-widget бакеты**, а не в один общий
  список (слои уже есть в Painter — обобщить до id-поддеревьев).
- Эффект: стационарный кадр из «`Egui::Label` 76µs × 48 + `Button`
  3 мс self + панель 2.6 мс» (разрез `FutureOptimizations.md`)
  → почти ноль; hover меняет ключ двух виджетов, остальные сотни
  отдаются из кэша.
- Инвалидация тривиальна для нашего скоупа: нет JS, который может
  переломать DOM в любой момент — монетизируем преимущество
  подмножества.

## 2. Damage tracking + частичный презент

Раз команды кэшированы по виджетам (§1), появляется dirty-регион:
пересобрать и переэмитить только изменившиеся бакеты, остальное —
replay. На render-потоке уже есть `replay_last` (`loop_redesign.md`
§8) — расширить с «все команды не изменились» до «изменились эти».

- Hit-test по retained-геометрии из Memory (rects уже пишутся):
  движение курсора над 1000 иконок перестаёт быть полноценной
  пересборкой кадра — перестройка только если hover-состояние
  реально переключилось, и тогда только два виджета.

## 3. Нулевая аллокация в стационарном кадре

Текущие источники (замеры в `FutureOptimizations.md`):

| что | цена |
|---|---|
| `effective_style` — новый `Style` на кнопку на кадр (merge каскада) | 193 аллокации/кадр |
| `Memory#interact` — шесть хэшей на виджет (`@widget_rects/@widget_senses/…` + seen/used) | ~1200 хэш-операций/кадр |
| `Icon.cached` — строковый ключ `"lucide/arrow-up/255/255/255"` | ~1.25 мс/кадр (уже в плане там же) |
| `Svg#paint` raster-lookup — хэш всего source (~700 байт) на иконку | ~0.8 мс/кадр (уже в плане) |

Направления:

- **Frame arena**: bump-аллокатор на кадр, сброс в `end_frame`.
  Не ждать `--gc=none` из `crystal_arenas_plan.md` — арена на уровне
  движка делается сейчас, без изменений языка.
- **Слоты вместо хэшей**: id → integer slot один раз, per-frame
  данные в параллельных массивах (SoA). Шесть `Hash`-обращений →
  один индекс.
- **Style sharing** (как Servo): виджеты с одинаковым
  `(классы, state, родительский стиль)` делят один разрешённый
  стиль. Каскад-merge один раз на класс-набор, не на кнопку.

## 4. Кэш тесселяции + SDF/instancing — убрать ~30k FFI-вызовов/кадр

Каждый rounded rect ≈ 24 квада, текст — квад на глиф; sgl-эмиссия —
узкое место после CPU-части (прогноз в `FutureOptimizations.md`).
Усиливается §1: раз paint-команды кэшированы по виджетам, меш
кэшируется тем же ключом — переэмитить только грязные бакеты.

- **SDF-квад** для rounded rect: 1 квад вместо 24 (прецеденты —
  sdf-эксперименты в tmp/, `sdf_circle_probe.cr` и серии скриншотов).
- **Instanced draw** для текста: квад на глиф, UV в атлас, один
  draw call. Место, где GL-пайплайн честно обгоняет Skia браузера
  на UI-примитивах.

## 5. Инкрементальный layout

Кэш галлеев уже сделан (`spec/layout_cache_budget_spec.cr`, MRU →
байтовый бюджет). Тот же принцип на box-дерево:

- memo по `(content-hash, constraints)`;
- инвалидация снизу вверх: изменилась ширина узла → пересобрать
  родителя, братья — из кэша;
- полный перемер — только на ресайз (как сегодня в `virtual:`
  scroll, но автоматически для всего).

## 6. Компиляция каскада — то, что браузер не может в принципе

exml-кодоген (`NativeHTML.md` §6) планируется как «литералы
`Array(Node)`». Расширить: для статических class-path **резолвить
каскад на этапе кодогена**, emit плоские resolved-структуры. В
рантайме — только delta за `:hover`/`active`.

- Селекторы → битсеты; класс-набор → perfect-hash индекс стиля.
- Браузер платит за selector matching каждый кадр; мы платим один
  раз на билде. Самый честный ответ на вопрос «чем компилируемость
  даёт скорость».

## 7. Мелочи (дёшево, снять константы)

| что | фикс | эффект |
|---|---|---|
| `Painter#commands_in_layer_order` O(слои×команды) | один проход, бакеты по z, конкатенация | ~0.3 мс |
| `Icon.cached` строковый ключ | tuple-ключ `{provider, name, tint}` | ~0.8 мс, ноль аллокаций |
| `Svg` raster-lookup | ленивый `@raster_key` — хэш source один раз в жизни инстанса | ~0.7 мс |

(§7 = пункты 2–4 текущего плана в `FutureOptimizations.md`, здесь
сведены для полноты.)

## Критерий готовности

1. **Дефолтный быстрый путь**: `bin/html_gallery` БЕЗ единого
   ручного opt-in (без `virtual:`, без `measure_cached`) показывает
   те же ~1–2 мс dev p50, что сегодня даёт ручной тюнинг
   (`FutureOptimizations.md`): быстрый путь — свойство движка.
2. **Hover-кадр**: движение курсора по статичному экрану иконок
   (lucide-бенч) — перестройка только затронутых виджетов; счётчик
   rebuilt-widgets/кадр в телеметрии.
3. **Стационарный кадр**: ноль аллокаций в установившемся режиме
   (счётчик аллокаций между `begin_frame`/`end_frame`).
4. **Oracle по времени**: сравнение с браузером не только по
   скриншотам (oracle/ уже есть), но и по времени кадра — иначе
   «быстрее браузера» нечем подтвердить.
5. Спеки `spec/*_spec.cr` зелёные на каждом этапе; меряем в DEV
   (политика `FutureOptimizations.md` — release не смотрим никогда).
