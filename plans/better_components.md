# exml: план закрытия недостатков (сравнение с GtkBuilder/QML)

Контекст: сверка exml с отраслевыми декларативными UI (GtkBuilder
`.ui` + GTK4 `<lookup>`-биндинги, QML как потолок категории, XAML,
Flutter-делегаты). Сильные стороны exml, которые НЕ трогаем: hot-reload
с сохранением состояния по Id (уровень Flutter, у GtkBuilder нет),
линт на сборке, ECSS-каскад, логика в компилированном Crystal без VM,
нулевые зависимости.

**Жёсткое ограничение всего плана:** обратная совместимость. Уже
написанные программы и документы обязаны собираться и работать без
правок — новые возможности только ДОБАВЛЯЮТ атрибуты/элементы/методы,
старые сигнатуры и семантика не меняются. Каждая фаза стартует с
прогона полного suite (820+ примеров) и завершается им.

## 1. Локальный стейт компонентов — РЕАЛИЗОВАНО

`ScopedRuntime < Runtime` (`src/egui/exml.cr`): каждый use-сайт
компонента получает собственный скоуп (кэш по `node.path` — путь
стабилен между кадрами и уникален per-сайт).

- Чтения: локально → fallback в глобальный store (слоты модели
  приложения остаются достижимы из шаблона: `{doc_text}` и т.п.).
- Записи (биндинги виджетов, `setup`/`update`) и регистрация экшенов —
  локально: коллизий с глобальным namespace больше нет в принципе.
- Экшены: локальный реестр → fallback в глобальный (`on_click="quit"`
  в шаблоне компонента по-прежнему стреляет приложенческим экшеном).
- API не изменился: `setup(rt)`/`update(ctx, rt)` получают тот же тип;
  `#rt` — скоуп сайта. Два `<counter/>` — независимые стейт и Id.

Изменение поведения (задокументировано, единственное): слоты,
засеянные компонентом, больше не видны приложению в глобальном store
(раньше утекали туда). Паттерн «компонент пишет, приложение читает»
заменяется на «приложение публикует, компонент читает (fallback)».

Спеки: независимость двух сайтов (клик в один — второй не меняется),
отсутствие утечки в глобальный store, чтение глобального слота,
глобальный экшен из шаблона.

## 2. Атрибуты раскладки — первая очередь

`row`/`column`: `spacing="8"`, `pad="4"` (или `pad.x/pad.y`),
`align="start|center|end"` (поперечное выравнивание детей),
`wrap="true"` у row. Виджеты: `min_width`/`min_height`/`grow`.
Всё additive: атрибуты опциональны, парсер/линт расширяются таблицей,
рендерер применяет через существующие `Ui`-примитивы (spacing уже
есть в style.spacing — значения атрибутов перекрывают на вызов).
Спека: лейаут-математика headless по RectCmd.

## 3. Линт слотов/экшенов

Приложение декларирует словарь: `Exml.validate(doc, known_custom: …,
slots: {"doc_text", "selected", …}, actions: {"save", …})`. Линтер
сверяет каждый `bind=`/`{интерполяцию}`/`on_click`/`on_change`/`on_button`
против списка. Неизвестное — issue на сборке, а не `{oops}` в UI.
Additive: списки опциональны (как known_custom), без них поведение
прежнее. Спека: опечатка `bind="spead"` ловится.

## 4. Параметры partials (дизайн, отложено)

`<partial id="field" params="label,key">` + `<use partial="field"
label="Speed" key="speed"/>`; подстановка только ОБЪЯВЛЕННЫХ
параметров в значения атрибутов НА ПАРАСЕ (макроподстановка), динамика
не ломается: `key="{selected}"` после подстановки остаётся рантайм-
интерполяцией. Пути — уже решено (префикс use-сайта). Риски:
двусмысленность `{param}` vs store-слот при совпадении имён — правило
«параметр затеняет слот только внутри partial, только если объявлен».

## 5. Delegates / repeat — v1 РЕАЛИЗОВАНО как `<repeat>`

`<repeat for="item" in="items" key="id">…</repeat>` — v-for:
- данные: слот-коллекция `rt.rows["items"] = Array(Hash(String, String))`
  (один уровень вложенности, числа приложение форматирует само);
- рендер: скоуп per-строку (`ScopedRuntime`), поля строки
  флаттятся в него как `item.<field>` — интерполяция/bind работают
  без изменений (regex `{…}` расширен до пунктирных ключей);
- `_i` — индекс строки (и в тексте `{_i}`, и в root-store перед
  вызовом экшена из строки — приложение читает `rt.string("_i")`);
- `key="field"` — стабильные пути/Id при пересортировке (урок `:key`);
- отсутствующий слот — warn-once, пустой рендер.

Не в v1 (по потребности): вложенные списки (внутренний `_i`
затирает внешний — обходить через `key` + собственные слоты),
двусторонний биндинг в строки (write-back коллекции — нужен дизайн
identity/диффа), анимации вставки/удаления.

Исходная заметка дизайна (сохранена для истории): обойти элементы,
скоуп per-элемент, стабильный key — всё реализовано поверх
ScopedRuntime без нового рантайма, как и планировалось.

## 6. Авто-биндинги/выражения — СОЗНАТЕЛЬНО отложено

`{count * 2}` = expression-движок = горка, обсуждена дважды.
Позиция: не делаем, пока бинарник-считает-кладёт-в-store не станет
реальной болью на конкретном экране. Если понадобится — грамматика
только pure-expressions (без присваиваний/потока управления), AST
компилируется на парсе, вычисление в кадре или на смене слота.

## 7. `<slot>`-ы (отложено)

`<partial id="panel">…<slot/></partial>` + дети `<use>` втекают в
слот. Требует либо рантайм-вставки (возврат к отклонённому дизайну),
либо парс-тайм сплайсинга с маркерами — второй вариант совместим с
текущей архитектурой, дизайн на отдельную сессию.

## 8–10. i18n / a11y / tooling (отложено)

- i18n: `translatable="yes"` + таблица переводов в Runtime — механика
  интерполяции уже готова (`{…}`), нужен только источник таблицы.
- a11y: блокируется отсутствием accessibility-слоя в egui.cr —
  сначала ядро (это отдельный большой план, не exml).
- JSON-schema для редакторов: генерация из ATTRS_BY_KIND — полдня,
  даёт автодополнение в VS Code без визуального редактора.
