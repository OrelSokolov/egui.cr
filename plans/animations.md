## Текущее состояние (проверено по коду)

Инфраструктура — есть, минимальная:

- **`AnimationManager`** (`src/egui/state.cr:265-312`): Id-keyed
  анимации **скаляров** (`Float64`), retarget mid-flight (смена цели
  перезапускает с текущего значения), `running?` для планирования
  репейнтов. Easing зашит жёстко — smoothstep (`t*t*(3-2t)`,
  `state.cr:309`), выбора кривых нет.
- **`Context#animate_value_with_time`** (`src/egui/context.cr:505`):
  обёртка + автоматический `request_repaint`, пока анимация не уляжется.
  Паттерн «спим до конца анимации» уже правильный для 0%-CPU цели.
- **Интерполяции**: `Color32#lerp` (`src/egui/color.cr:33`),
  `Vec3#lerp` (`src/egui/math3d.cr:59`). Vec2/Rect — нет.
- **`request_repaint`** + непрерывный режим (spinner крутит каждый
  кадр осознанно).

Использование — все анимации hand-coded, по одному месту на виджет:

| Где | Что | Длительность |
|---|---|---|
| `progress_bar.cr:36` | fill к цели | 0.3s |
| `toggle_button.cr:83` | флип: lerp цвета + позиция knob | 0.15s |
| `expander.cr:88-92` | слайд по измеренной высоте | 0.2s |
| `spinner.cr` | непрерывное вращение | ∞ |
| `text_edit`/`textarea` | мигание каретки | ∞ |
| `plot.cr` | анимированный pan/reset | — |

Чего нет (это и есть «встроенная фича»):

1. **Стилевых transitions** — аналога CSS `transition`. Смена
   hover/фокус/active-состояния у большинства виджетов мгновенная:
   все `fade_color(...)` в коде — статические полупрозрачные миксы,
   а не анимации.
2. **Библиотеки easing** — одна зашитая кривая.
3. **Анимации нескалярных значений** — менеджер скалярный; цвета
   лерпаются руками рядом с ним.
4. **Enter/exit-анимаций** — меню/попапы/тосты появляются и исчезают
   мгновенно; исчезнувший виджет не выполняется — анимировать некому.
5. **Общего механизма анимации layout-размеров** — expander
   единственный пример, паттерн (анимировать аллокацию per-frame,
   соседи съезжают) доказан, но не обобщён.
6. **prefers-reduced-motion** — нет.

## Дизайн

Ключевое наблюдение: модель CSS transitions ложится на ECSS и на
immediate mode почти без трений — каждый кадр и так пересчитывает
каскад и лейаут, поэтому «анимированное значение» = «обычное
значение, интерполированное от прошлого кадра», и анимация ширины
(главный мобильный кейс) работает из коробки, expander это уже
доказал.

### Уровень 1 — `transition` в ECSS (ядро фичи)

```css
button {
  transition: background 120ms ease-out,
              fill 120ms ease-out,
              width 200ms ease-in-out;
}
button:pressed { fill: #3d5afe; width: 96%; }
```

Механика — в слое разрешения каскада, универсально для всех виджетов:

- кэш резолвнутых значений на `(widget id, var key)`;
- кадр N: каскад дал новое целевое значение → в кэше лежит прошлое →
  анимируем от прошлого к новому; цель сменилась mid-flight —
  retarget с текущего (семантика `AnimationManager` сохраняется);
- типы значений: `Color32` — через `lerp`, числа и длины (после
  Этапа 1 `responsive-mobile.md` — да, проценты анимируются:
  интерполируем в px) — через скалярный менеджер; строки/bool —
  не анимируются, меняются мгновенно;
- repaint — существующий (`running?` → `request_repaint`);
- анимируются только переменные, перечисленные в `transition`
  (как в CSS) — это и производительность (не интерполировать всё),
  и предсказуемость.

Скрытый бонус: hover/pressed/focus переходы у ВСЕХ виджетов
становятся плавными без единой строки в виджетах — интерполяция
стоит в каскаде до того, как виджет прочитал переменную.

### Уровень 2 — easing и доступность

- Именованные кривые: `linear`, `ease`, `ease-in`, `ease-out`,
  `ease-in-out`, `smoothstep` (default, обратная совместимость с
  текущим поведением), потом при необходимости `spring` (перелёт с
  затуханием) и `cubic-bezier(x1,y1,x2,y2)`.
- `prefers-reduced-motion` — глобальный флаг контекста
  (тема/пользователь/системная настройка ОС): при включении все
  durations → 0, transitions отключены. Уважение системной
  настройки — та же shim-работа, что fontScale из
  `responsive-mobile.md` Этап 5.

### Уровень 3 — enter/exit (самое сложное, последним)

Проблема immediate mode: исчезнувший виджет не рисуется — некому
анимировать выход. Двухчастное решение:

- **Enter** — дёшево: ключ по id, первые кадры существования виджета
  интерполируют `opacity`/`translate` от 0. В стилях:
  `enter: fade 150ms` / `enter: slide-up 200ms` на классе.
- **Exit** — требует контракта «задержанного удаления»:
  контейнер (меню/попап/тост) вместо мгновенного исчезновения
  помечает себя «closing» и дорисовывается N кадров с обратной
  анимацией; фреймворк даёт хелпер `ui.closing?(id, ms)` — виджет
  узнаёт, что надо бы ещё порисоваться. Начать с мест, где мы
  владеем жизненным циклом (menu, combo_box flyout, toast-слой).

### Уровень 4 — код-API (для виджетов и приложений)

Обобщение существующего менеджера со скаляров на значения:

```crystal
ctx.animate_value_with_time(id, target, duration)             # есть
ctx.animate_color_with_time(id, target : Color32, duration)   # добавить
ctx.animate_vec2_with_time(id, target : Vec2, duration)       # добавить
ctx.animate_with(id, from, to, duration, easing)              # общая точка
```

Ручные анимации существующих виджетов переводятся на неё без
изменений поведения.


## Спеки

- `spec/animations_spec.cr`: retarget mid-flight, easing-кривые
  (значения в контрольных точках), duration 0 = мгновенно,
  reduced-motion гасит всё, `transition` парсится и дампится
  (round-trip как у остальных ECSS-значений);
- каскад: hover-переход меняет цвет через t=0.5 — виджет читает
  интерполированное значение;
- ширина: `transition: width 200ms` + смена percent-ширины —
  rect виджета растёт по кадрам (headless, время прокрутить руками).

## Риски

- Кэш `(id, var)` живёт в памяти → авто-id (0x…) виджетов,
  меняющих позицию в дереве кода, дадут дёрганые переходы;
  фикс — явные id у анимируемых (тот же вывод, что у inspector/
  element-правил ECSS).
- Интерполяция длины в px при resize окна: цель скачет каждый
  кадр → retarget-шторм. Лечится: при resize репейнт и так
  каждый кадр, анимация доехает до новой цели; при желании —
  отключение transition на layout-переменных во время resize.
- CPU: все анимации будят кадр только до своего конца (паттерн
  уже есть) — деградации к 0%-CPU цели нет; непрерывные
  (spinner/caret) — осознанные исключения, как сейчас.
