# Курс: Vue-модель + прокси-бэкенд → паритет с Raven

Зафиксированное архитектурное решение (обсуждение 2026-11-13). Не «ещё один
план», а курс: все следующие PR сверяются с этим документом.

## 0. Определение «идеала»

Raven (`tmp/Raven`) — эталон: C11, **retained** + damage tracking,
**рендер-поток** отдельно от UI-потока, шейдерный бэкенд. Быстр не
интеллектом, а устройством — пока ничего не меняется, не делает ничего.
(`plans/FPS_OPTIMIZATION.md` сформулировал то же для браузера: retained +
damage + кэш растеризации.)

Цель по измерению: FPS на сценах `bench/raven_bench.cr` / oracle-сценах
raven_music **не ниже Raven** на тех же сценах. Тихий кадр (без ввода и
анимаций) не ходит по дереву виджетов вообще.

## 1. Реактивность: Vue, не React (решено)

Модель — Vue/Solid: сигналы как ПОВОД кадра, полный проход `update()` как
ВЫВОД. Не React: VDOM и reconciliation в immediate mode не нужны — нечего
диффить, дифф = второе дерево и лишний проход (`egui-reactive.md` non-goals).

Слои и их Vue-аналоги (уже стоят или строятся):

| egui.cr | Vue-аналог | статус |
|---|---|---|
| `reactive.cr` (сигналы, computed) | reactivity core | фаза 1 ✅ |
| EXML-шаблоны | SFC-шаблоны | ✅ |
| immediate run `update()` | render-функция | ✅ |
| retained paint-бакеты по ключу | targeted updates | этап 2 ч.1 ✅ (Button/Label) |
| dirty-регион + частичный replay | патчинг дельты | **этап 3 — следующий** |

Из React берём только: ключи списков (первоклассные `key` в EXML),
memo-границы как явное API над кэшем бакетов, однонаправленный поток.
Solid-стиль (обновление без перезапуска компонента) НЕ берём: полный проход
в immediate mode дёшев, запрещать его — усложнение без выгоды.

## 2. Прокси-бэкенд (port/adapter)

Проблема: приложения жёстко зовут `Backend::Sokol.run` (ARCHITECTURE.md A1),
рендер-логика размазана по sgl-вызовам и шиму.

Решение — гексагонал, который уже наполовину стоит:

- **Порт** (язык, независимый от бэкенда): поток `PaintCmd` из `painter.cr`
  + `Driver::Base` (`driver/base.cr`). Расширять только его.
- **Адаптеры**: `driver/sokol.cr`, `capybara/raster.cr`, будущие.

Этапы:

1. `Egui.run(app, **opts)` — селектор бэкенда (compile-time флаг), примеры
   меняют одну строку. `Backend::Sokol.run` остаётся для sokol-специфики.
2. Горячий путь рендера переводится с `sokol_gl` (фиксированный формат
   вершины, отсюда CPU-тесселляция градиентов) на собственные инстансированные
   пайплайны поверх **сырого sokol_gfx**. sokol_gfx НЕ меняем — это и есть
   тонкая абстракция над OpenGL/Metal/D3D; свою такую писать не нужно.
   sgl остаётся для редко рисуемого мусора, затем удаляется.
3. Skia НЕ берём: тяжёлый C++-билд противоречит легковесности; нужного
   (инстансированные квады + SDF + градиентные рампы + атлас глифов) хватает
   своего слоя, что SDF-батч уже доказал.

## 3. Градиенты — через шейдер, не тесселляцию

Общий CSS-градиент (`cmd.gradient`): сегодня CPU-тесселляция (радиальный —
до 48 колец × периметр, каждый кадр). Перевести на аналитику в SDF-батче:

- параметры градиента (kind, угол / cx,cy,r) — в spare-слоты инстанса
  (`[36..39]`, `sokol_shim.c` layout);
- мультистопы — 1D ramp-текстура: стопы бейкаются один раз (кэш по
  градиенту), шейдер считает `t` и делает один texelFetch (как браузеры/Skia).

## 4. Шрифты

Отдельный план: `plans/fonts_optimizations.md` (dirty-рект аплоад вместо
16 МиБ заливки, квантизация размера глифа, общий атлас + epoch + LRU,
асинхронная загрузка файлов при старте; растер глифов — синхронный).

## 5. SDF сломан — чиним автоматикой, не руками

Принцип: ручная отладка шейдеров запрещена процессом. Паритет доказывается
A/B-скриншотами: oracle-стенд (twinshot, `oracle/`) гоняет сцену с SDF=0 и
SDF=1, диф — список багов. Существующие ножи `EGUI_SDF` / `EGUI_NOGRADIENTS`
уже дают ноги для A/B; недостаёт реестра сцен (см. §7). SDF остаётся
opt-in до зелёного twinshot-отчёта по всем сценам реестра.

## 6. Не ходить по дереву каждый кадр

Боль: обходы виджетов — главный CPU-лимит крупных сцен (этап 2 лог:
`+child_ui+Id ≈ 20 мкс × 400` узлов, реплей ~11 мкс × 400).

Порядок работ (продолжение FPS_OPTIMIZATION):

1. **Этап 3: dirty-регион + частичный replay** — тихий кадр не переэмитит
   всё; сигналы из §1 дают «что изменилось», бакеты — «что сохранить».
2. Сигнальные гейты: поддерево с чистыми входами пропускается целиком
   (memo-границы из §1 как API).
3. Рендер-поток: реплей меша уходит с UI-потока (`loop_redesign.md` §8),
   как у Raven.

## 7. Критерии приёмки (definition of done)

- [ ] `Egui.run(...)` во всех примерах; второй бэкенд компилируется за флагом.
- [ ] Тихий кадр на raven_music-сцене: 0 эмитов paint-команд (счётчик в
      `EGUI_DRAW_STATS`), кадр < 1 мс CPU.
- [ ] Градиенты: 0 CPU-тесселляции (один инстанс на прямоугольник + рампа).
- [ ] Атлас глифов: аплоад ≤ dirty-рект (не 16 МБ на новый глиф), ключ
      кэша — квантованный размер.
- [ ] twinshot: SDF=1 vs SDF=0 — диф пуст по всему реестру сцен.
- [ ] bench: FPS ≥ Raven на тех же сценах, release-сборка.
