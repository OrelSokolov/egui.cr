# exml: SFC-генератор (разметка-first компоненты) — ОТЛОЖЕНО

**Статус.** Идея обсуждена и осознанно отложена: слишком много магии
(сгенерированный код, отдельная директория, сдвиг номеров строк в
ошибках) при нулевой новой capability — всё то же умеет текущая схема
`Egui::Exml::Component` (`src/egui/exml.cr`), где главным файлом
компонента является `.cr`-класс с макросом `exml "path"`. Вернуться,
если компонентов станет много и бойлерплейт класса начнёт резать
глаза; оба механизма мирятся — генератор производил бы те же классы
поверх того же `Component`, переделок не требуется.

## Идея (Vue SFC наоборот: разметка первична)

Один файл на компонент — `assets/components/counter.exml` — содержит
обе половины: `<script>` с Crystal-методами и разметку:

```xml
<script>
def setup(rt)
  rt.floats["count"] = 0
  rt.actions["inc"] = ->bump
end

def bump : Nil
  rt.not_nil!.floats["count"] += 1
end
</script>

<button on_click="inc">You clicked me {count} times.</button>
```

Сборщик по конвенции подхватывает «голые» `.exml` из каталога и
генерит класс за автора (rake-таска с mtime-зависимостями →
`gen/components/counter.cr`, регенерируемый, руками не правится):

```crystal
class ExmlComponents::Counter < Egui::Exml::Component
  template_path "assets/components/counter.exml"
  # вшитый шаблон с вырезанным <script> (fallback автономного бинарника)

  def setup(rt)      # ← дословно из <script>
    rt.floats["count"] = 0
    rt.actions["inc"] = ->bump
  end

  def bump : Nil
    rt.not_nil!.floats["count"] += 1
  end
end
```

Плюс barrel-файл со списком сгенерированных — приложение регистрирует
все компоненты одной строкой. Дропнул `.exml` в каталог → следующий
билд подобрал → `<counter/>` работает.

## Что нужно сделать, если вернуться

1. Парсер: вырезать `<script>…</script>` как комментарий — и на
   `parse`/`parse_fragment` (hot-reload обязан получать чистый
   шаблон), и на этапе генерации (извлечь текст методов). Сейчас
   парсер текст между тегами не хранит вовсе — нужен точечный захват
   сырого текста внутри `<script>`.
2. Rake-таска `build:exml_components` (mtime по каждому файлу,
   регенерация только изменившихся) + зависимость от неё в
   `build:examples`.
3. Экранирование разметки при вшивании в `#template` (heredoc с
   маловероятным делимитером; кавычки в атрибутах).
4. Спеки: генерация класса из фикстуры, вырезание `<script>`,
   hot-reload шаблона с `<script>` внутри, регенерация по mtime.

## Почему отказались (решение 2026-10)

- Ошибки в кристал-коде внутри `<script>` указывают на строки
  СГЕНЕРИРОВАННОГО файла — навигация по ошибкам ломается.
- Сгенерированная директория в билде/git, гонка свежести, CI-проводка.
- Редакторская подсветка кристал-кода внутри XML отсутствует.
- Всё перечисленное — цена формы авторинга (`.exml` первичен вместо
  `.cr`), не функциональности. При единичных компонентах текущая
  схема без этих издержек.
