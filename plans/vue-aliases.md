# exml: Vue-совместимый синтаксис директив (v-* как parse-time алиасы)

Решение 2026-11-11: exml принимает НАПИСАНИЕ директив Vue как
алиасы, десугарящиеся на парсе в существующее дерево `Array(Node)`.
Модель одна — Vue (React-стиль осознанно не тянем). Мотивация:
семантика exml уже 1:1 с шаблонами Vue (repeat = v-for, bind =
v-model, on_click = @click, {интерполяция} = :prop), а знакомое
написание превращает порт готового Vue-компонента в copy-paste
`<template>` + механическую замену значений. CSS-половина уже
портируется через ECSS; это закрывает шаблонную.

**Формула подмножества: форма Vue, значения наши.** Значение
директивы — голое имя слота/экшена/поля, никакой JS-выражений
(`v-if="count > 0"` — ошибка парса с понятным текстом, не молчание).
Expression-движок отвергнут навсегда (egui-reactive.md non-goals,
better_components.md §6) — второй закон NativeHTML («никаких
полусвойств») требует, чтобы отсутствие было ЯВНЫМ.

## Что не требует новой работы (уже 1:1)

| Vue | egui.cr (каноничное имя) | Где |
|---|---|---|
| компонент + props | `<Counter start="5"/>`, атрибуты use-сайта → props | `seed_props` (exml.cr:753) |
| `ref` / `:key`-стабильность | `id=` → `renderer.ref(name)`; `key=` у repeat | exml.cr:77, §5 ниже |
| `{x}` в теле / `:text` | интерполяция `{slot}` в любом атрибуте и тексте | `Runtime#interpolate` |
| SFC (template+script+style) | `.exml` + `.cr`-класс `Component` + `.ecss` | README: «Vue SFC shape, script half in compiled Crystal» |

## Таблица алиасов (десугар на парсе)

| Vue | → канонический атрибут | Правило |
|---|---|---|
| `v-if="flag"` | `if="flag"` | голый слот |
| `v-show="flag"` | `if="flag"` | семантика совпадает: наш `if=` пропускает рендер, но память виджета живёт по Id-пути (exml.cr:22-25) — как display:none у Vue, состояние не теряется |
| `v-model="name"` | `bind="name"` | модификаторы `.number/.lazy/.trim` — ошибка линта |
| `v-text="name"` | `text="{name}"` | |
| `@click="save"` / `v-on:click="save"` | `on_click="save"` | голый экшен; инлайн-выражения (`@click="a(); b()"`) — ошибка |
| `@change="save"` / `v-on:change` | `on_change="save"` | |
| `v-bind:title="x"` / `:title="x"` | `title="{x}"` | значение — имя слота; `:x="5"` (литерал) → подсказка «пишите `x="5"`» |
| `v-for="item in items"` | синтез `<repeat for="item" in="items">` вокруг ноды | см. ниже |
| `v-for="(item, i) in items"` | то же + алиас индекса | `i` → доп. слот строкового скоупа рядом с `_i` |
| `:key="item.id"` | `key="id"` | префикс `<var>.` отбрасывается; иначе — ошибка (ожидается имя поля) |

НЕ входит в подмножество (ошибки/линт, зафиксировать в SPEC.md):
`v-html` (нет сырого HTML), `v-else`/`v-else-if` (v1; см. Этап 6),
`v-once`/`v-memo`/`v-pre` (кэш интерполяций уже есть), `<template>`
-обёртки, `v-slot`/`<slot>` (better_components.md §7), `<script
setup>` (логика — Crystal, это фича, не пробел).

## Реализация

### 1. Парсер: имена атрибутов

`parse_tag` (exml.cr:473): регекс `[a-zA-Z_][a-zA-Z0-9_]*` не
пропускает ни `v-if` (дефис), ни `:title`, ни `@click` — сейчас они
уйдут в «junk»-warning и будут молча отброшены. Расширить имя до
`[v@:]?[a-zA-Z_][a-zA-Z0-9_.-]*` (префикс v-/(':', '@' + суффикс
после v-: `v-bind:title`, `v-on:click`), симметрично поправить
детектор мусора (exml.cr:476). Прецедент: цифры в именах (шаг 2
music-exml-stage2) — та же точка.

### 2. Десугар атрибутов — чистый rename

Точка: `parse_tag` после сбора attrs (до конструирования `Node`):
переименовать `v-*`/`@*`/`:*`/`v-bind:*`/`v-on:*` по таблице,
`v-model`→`bind`, `:x="y"`→`x="{y}"`, `:key` (внутри v-for) —
особый случай. Значение с пробелами/операторами вне `{…}` →
parse-issue `path: v-if="count > 0" — выражения не поддерживаются,
опубликуйте слот`. После rename нода строится канонической —
`Node#initialize` (exml.cr:204), `ATTRS_BY_KIND`/`validate`
(exml.cr:801/845) и рендерер НЕ меняются вовсе.

### 3. `v-for` — синтез Repeat-обёртки

Пост-парс проход по дереву (прецедент парс-тайм перезаписи —
`expand`/`repath`, exml.cr:422/456): нода с `v-for` заменяется
в родительском children на `Repeat` (обёртка занимает путь исходной
ноды), ребёнок — исходная нода без `v-for`, с `for=`/`in=`/`key=`
на обёртке. Поещёчные пути строк берёт существующий механизм
`children_under(prefix)` (exml.cr:247) — он уже ре-патит детей
repeat per key, ничего нового. `v-for` на `<use>` — не поддерживаем
в v1 (десугар идёт до expand партиалов; линт-подсказка «оберните
repeat вручную»).

Предупредить в доках: переписывание СУЩЕСТВУЮЩЕГО документа на
v-for-синтаксис сдвигает пути на один уровень (документ, написанный
с v-for с рождения, стабилен).

### 4. Индекс-алиас `(item, i)`

`render_repeat` (exml.cr:1375) сеет строковый скоуп: помимо `_i`
положить слот с именем из скобочной формы. Однострочная правка в
месте `scope.repeat_index = i` (exml.cr:1394).

### 5. Совместимость и кодоген

Канонические написания (`if=`/`repeat`/`bind`/`on_click=`) остаются
навсегда — алиасы additive. Десугар до дерева ⇒ кодоген уровня A
(NativeHTML §6) и hot-reload (`reload_if_changed`) не замечают
алиасов вообще: дерево то же, литералы те же.

### 6. `v-else` (v1.5, опционально)

Механическое зеркало: `v-else` на ноде, у предыдущего сиблинга
`if="slot"` → `unless="slot"` на этой. `v-else-if` НЕ выражается
(нужна инверсия слота) — не делаем.

## Риски

- **Мусор в Custom-атрибутах**: десугар трогает ТОЛЬКО `v-*`/`@*`/`:*`
  — неизвестные кастомным хендлеру атрибуты без префикса не
  переименовываются.
- **`:x` на Custom-элементах**: работает как `x="{slot}"` — тот же
  путь, что и у props компонентов (`seed_props`).
- **Двойное написание в доках**: розетта-таблица одна, канонические
  имена остаются первичными в шапке exml.cr; SPEC.md — единственное
  место, где подмножество Vue описано целиком.
