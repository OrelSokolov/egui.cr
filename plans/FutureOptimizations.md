# Оптимизации рендеринга: горячие места кадра

## Контекст и как мерить

`bin/lucide_icons` проседал до 60 fps при движении курсора над полным
экраном иконок (vsync off). Headless-бенчмарк
(`Egui::Bench`, `src/egui/bench.cr` + раннер `bench/lucide_bench.cr`)
показал, что CPU-часть кадра **до FFI/GPU** сама по себе съедала
~16 мс — то есть 60 fps объяснялись Crystal-частью, а не бэкендом.

Запуск (обязательно с реальным шрифтовым бэкендом, как в раннере):

```
crystal build bench/lucide_bench.cr -o bin/lucide_bench \
  --link-flags "-L$(pwd)/lib" && ./bin/lucide_bench
# стресс-режим без viewport-каллинга:
LUCIDE_NO_CULL=1 ./bin/lucide_bench
```

Замеры — по фазам кадра + агрегированные спаны (self/inclusive время,
стек как во flamegraph-профайлерах) + счётчики. Отчёт — килобайты,
независимо от числа виджетов.

## Уже сделано

| что | эффект |
|---|---|
| `Fonts#measure` — не тронут: инпуты (TextEdit/TextArea/…) работают как раньше | — |
| `Fonts#measure_cached` — opt-in кэш ширин для статических текстов (Button, подписи lucide). Ключ `(текст, физический размер, трекинг)`; инвалидация не нужна — все входы ширины в ключе; память ограничена фильтром длины (≤ 64 симв. — строки буфера и caret-префиксы мимо кэша) и cap'ом 8192 с clear-on-overflow | `Fonts#measure` 8.9 мс/кадр → ~0 |
| kern-кэш в `AtlasFonts#walk` (`kern_at`): ключ `(gid_prev, gid, size)` — пары glyph-id неизменяемого шрифта, текста в ключе нет, инпуты переиспользуют те же пары — загрязнение невозможно; cap 65536, clear-on-overflow | FFI-per-char в walk'е устранён |
| инструментирование ядра спанами/счётчиками (`Ui#add`/`#add_sized`, `Svg#paint`, `Fonts#layout`, `StyleSheet#resolve`, `Icon.cached`, `commands_in_layer_order`, deferred central panel) | нулевая цена вне бенчмарка |
| **Layout-кэш галлеев** (`fonts.cr`): MRU-кольцо на 8 записей → `Hash(LayoutKey, Entry)` с байтовым бюджетом (дефолт 4 MiB, `EGUI_LAYOUT_CACHE_BYTES`), поколенческое выселение: stale (≥3 кадров без использования, старейшие вперёд), затем LRU, до ¾ бюджета (гистерезис); тик поколения — `Context#end_frame`. Спека: spec/layout_cache_budget_spec.cr. | html gallery: miss 16590→398 (только прогрев), кадр p50 **3.10→1.51 мс** (323→663 fps CPU pre-FFI) |

## Кадровый бюджет (политика, 2026-11-10)

Владелец задал: кэшу текстов — **4 MiB минимум**; кадровый бюджет
**p99 ≤ 5 мс** (200 fps потолок — больше нигде не нужно), цель —
**2 мс** CPU-часть pre-FFI с учётом Crystal-специфики. Всё, что
вылезает за бюджет на реальном приложении — чиним по мере вылезания,
приоритет по бенч-спанам. **Меряем в DEV-сборке** — release не
смотрим никогда, это лучший случай.

### Сделано по политике (html_gallery, 1100×800)

| шаг | dev p50 | release p50 | команд/кадр |
|---|---|---|---|
| база | ~31 мс (реально ~20 fps) | 3.10 мс | 669 rounded + 884 glyphs |
| + кэш галлеев (байтовый бюджет 4 MiB) | 11.13 мс | 1.51 мс | то же |
| + `ScrollArea virtual:` (невидимые карточки не строятся) | **1.82 мс** | **0.28 мс** | 37 rounded + 710 glyphs |

Виртуализация — движковая: `ScrollArea.new(virtual: true)` +
`Ui#virtual_row(key)`; кэш высот/id-спанов в Memory (по id скролла),
ширина вьюпорта изменилась → полный перемер. Спеки:
spec/virtual_scroll_spec.cr. Первый кадр (и после ресайза) строит
всё — цена перемера, дальше только видимая полоса ± 128px.

Остаток dev-кадра: `Egui::Label` 76µs × 48 и `Egui::TextArea` 56µs ×
18 self — per-widget overhead; glyphs 710 — код-панели (моно-текст
видимых карточек). Следующие кандидаты по политике: тесселяция/эмиссия
бекенда (теперь от 37 rounded — сильно меньше), затем `bin/hello`
~3 мс как базовый ориентир.

Итог: **16.1 → 9.3 мс/кадр (p50), ≈ 108 fps CPU ceiling pre-FFI.**
Спеки: 406 примеров, зелёные.

Разрез кадра после (p50 9.29 мс, спаны ≈мс/кадр):

| путь | ≈мс/кадр |
|---|---|
| `Egui::Button` self | 3.0 |
| machinery центральной панели (scroll/columns/layout) | 2.6 |
| `Fonts#layout(miss)` — трэш кэша галлей | 2.2 |
| `Icon.cached` — интерполяция ключа-строки | 1.25 |
| `Svg#paint` self — raster-lookup хеширует весь source | 0.8 |

## План (по убыванию выигрыш/риск)

### 1. ~~Layout-кэш: массив → хэш~~ — ✅ сделано 2026-11-10

Сделано шире плана: не 512 записей с MRU, а байтовый бюджет 4 MiB +
поколенческое выселение (stale ≥3 кадров → LRU, до ¾ бюджета).
Рабочий набор экрана измерен (html gallery: 398 галлеев / ~208 KiB) —
бюджет покрывает его с 20-кратным запасом. Спаны «Fonts#layout(miss)»
в стационаре — ноль, см. таблицу выше.

### 2. `Icon.cached`: tuple-ключ вместо интерполяции строки — ~0.8 мс

На каждую иконку каждый кадр строится
`"lucide/arrow-up/255/255/255"` — аллокация + хэш. Ключ
`{provider, name, tint}` — ноль аллокаций, хэшируются те же строки,
но без построения новой.

### 3. `Svg` raster-lookup: предвычисленный ключ — ~0.7 мс

`@@raster_cache[{@source, @current_color}]` хеширует весь SVG-source
(~700 байт) на иконку на кадр. Дать Svg'у ленивый `@raster_key`-объект:
хэш source считается один раз в жизни инстанса, `==` через
`same?` + fallback по содержанию (кросс-инстансный шаринг текстуры
для свежих `ui.svg` сохраняется).

### 4. `commands_in_layer_order` — ~0.3 мс, тривиально

O(слои × команды) пересканирование → один проход с раскладкой по
слоям (бакеты по z, конкатенация).

### 5. Button (3 мс) и панель (2.6 мс) — сначала finer spans

Без догадок: врезать спаны внутрь `Button#ui` (каскад стилей /
measure / interact / painter) и в scroll/columns, посмотреть разрез.
Уже видимые кандидаты:

- `effective_style` строит новый объект `Style` на кнопку на кадр
  (merge каскада) — 193 аллокации/кадр;
- `Memory#interact` пишет в шесть хэшей на виджет
  (`@widget_rects/@widget_senses/@widget_layers/@widget_clips/...`
  + `seen_ids`/`used_ids`) — ~1200 хэш-операций/кадр на ровном месте.

Структурнее пунктов 1–4; лезть без замеров не стоит.

## Прогноз

Пункты 1–4: ~9.3 → **~5 мс/кадр (≈200 fps pre-FFI)**, спеки заметить
не должны.

Дальше потолок — бэкенд-часть: sgl-эмиссия ~30k FFI-вызовов на кадр
(каждый rounded rect ≈ 24 квада × 4 вершины, текст — квад на глиф).
Это отдельная тема: кэширование тесселированного вывода между кадрами
(в idle-режиме `on_frame` уже реплеит команды; расширить на
«команды не изменились → не переэмитить в sgl»).
