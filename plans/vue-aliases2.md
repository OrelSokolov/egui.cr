# exml: вторая порция Vue-совместимости (vue-aliases, этап 2)

Решение 2026-11-11: этап 1 (plans/vue-aliases.md) закрыт — `v-if`/
`v-show`, `v-model`, `v-text`, `@x`/`v-on:x`, `:x`/`v-bind:x`,
`v-for` (+`:key`, `(item, i)`), `v-else` десугарятся на парсе
(`desugar_vue_attrs` exml.cr:552, `desugar_vue_tree` exml.cr:634).
Здесь — что докидывать дальше, тем же критерием: **форма Vue,
значения наши, ноль JS-выражений** (второй закон NativeHTML —
отсутствие всегда явное). Всё разбито на ярусы по цене;
отвергнутое фиксируется в SPEC.md §7 так же, как в этапе 1.

## Ярус 1 — чистые parse-time алиасы (часы)

| # | Vue | → каноническое | Правило |
|---|---|---|---|
| 1 | `ref="name"` | `id="name"` | Vue template-ref семантически и есть `renderer.ref(name)` (exml.cr:77-79); rename в таблице `desugar_vue_attrs` |
| 2 | `<template if=/v-if>` | сплайн детей в родителя + `if=` на каждом | `<template>` — обёртка-группа БЕЗ ноды: механика `<use>`-splice (exml.cr:422) на новом имени; групповой `if=` копируется на каждого ребёнка (условие независимо, `visible?` уже так работает) |
| 3 | `<template v-for>` | синтез repeat с НЕСКОЛЬКИМИ детьми | та же `wrap_v_for` (exml.cr:670), но ребёнок не один — главный паттерн Vue-списков, сейчас обёртка завязана на одну ноду |
| 4 | `v-model.number="x"` | бинд во float-слот | вместо «ошибка линта»: `input` пишет `rt.floats[x]` (в движке есть `number_input` ui.cr:528, `drag_value` ui.cr:514 — вопрос лишь, добавлять ли их в словарь exml). `.trim` — trim при write-back; `.lazy` отвергнуть (on_change уже событийный) |

Специфика `<template>`: парсится как parse-time элемент (как
`partial`/`use` — `Kind::Template` в `KIND_BY_NAME`, в `ATTRS_BY_KIND`
пусто, в рендер не доходит: сплайн до `expand`). Цикл/вложенность —
по прецеденту `<use>`.

## Ярус 2 — реальная ценность, средняя работа

| # | Vue | → каноническое | Заметки по реализации |
|---|---|---|---|
| 5 | `@keyup.enter="save"` | хоткей-биндинг | значение — по-прежнему голое имя экшена, `.enter` — ИМЯ КЛАВИШИ, не выражение. Десугар в атрибут `hotkey="enter"` + `on_keyup="save"`; рендерер регистрирует через `ctx.hotkeys.bind` (hotkeys.cr:177). Снимает давнее ограничение exml «hotkeys — markup показывает только hint» (exml.cr:29-30) — шапку обновить. Ограничить `Hotkey.parse?`-набором (enter/esc/tab, ctrl+…), остальное — issue |
| 6 | `<component :is="name">` | `is="slot"` → диспетчеризация | рендерер читает слот (имя элемента), смотрит в `@custom`/`Exml.widgets`; стабильность Id — путь по `component[0]`, состояние разных элементов НЕ общее (это фича) |
| 7 | `v-bind="settings"` | спред полей слота в пропсы | расширение `seed_props` (exml.cr:999): значение — голое имя слота, его поля сеются как пропсы (конфиг-подобные пропсы). `v-bind="x"` без `:`-аргумента — новый случай в `desugar_vue_attrs` |

| 9 | `<transition name="fade">` | проводка к appear/`animation:*` | анимационный стек уже есть (appear.cr, ECSS `appear:`/`animation:*`, keyframes); алиас лишь назначает appear-вид по имени. Сначала убедиться, что семантика enter/leave ложится на appear — иначе полусвойство |

## Ярус 3 — отвергнуто навсегда (держать в SPEC.md §7)

- **Выражения** — non-goal (egui-reactive.md, «никаких полусвойств»).
- **`v-else-if`** — в общем виде не выражается: цепочка требует
  несколько `unless=` на ноде, а attrs — hash. Дырка: ОДИН
  `v-else-if="b"` после `v-if="a"` выражается парой
  `if="b" unless="a"` — `visible?` (exml.cr:1708) проверяет оба
  гейта. Хотим — добавить как спец-случай зеркала v-else; глубже
  цепочки — идиоматический exml просит слот-дискриминатор
  (`if="{active_tab}"`).
- **`v-slot`/`<slot>`** — better_components.md §7: пропсы вместо слотов.
- **`v-html`** — markdown есть, но семантика другая; алиас был бы
  полусвойством.
- **`v-once`/`v-memo`/`v-pre`** — кэш интерполяций уже решает.
- **`<keep-alive>`** — память по Id-path и есть архитектура.
- **Фильтры `|`** — выражения.

## Порядок работ

| # | Шаг | Оценка | Спеки |
|---|---|---|---|
| 1 | `ref=` → `id=` | час | rename; `renderer.ref` видит его |
| 2 | `<template>`-группы: if-копия + сплайн | полдня | групповой v-if гейтит всех детей; дети на местах родителя (пути стабильны) |
| 3 | `v-for` по нескольким детям (`<template v-for>`) | полдня | те же RectCmd, что у рукописного repeat с N детьми |
| 4 | `v-model.number` | часы | float-слот после инпута; `.trim` |
| 5 | `@keyup.enter` → hotkey | ~день | клавиша firing-ает экшен без фокуса; шапка exml.cr обновлена |
| 6+ | `:is`, `v-bind=`, `v-model:prop`, `<transition>` | по потребности | каждый — отдельный мини-план в этом файле |

Регресс тот же: полный `crystal spec` до/после шага; канонические
assets/*.exml дают то же дерево (`Exml.warnings` пуст).

## Риски

- **Шаг 3 (multi-child v-for)**: обёртка занимает путь исходной
  ноды — при переписывании СУЩЕСТВУЮЩЕГО документа на template-форму
  пути сдвигаются (тот же caveat, что в этапе 1; рождённые в новом
  синтаксисе — стабильны).
- **Шаг 5 (хоткеи из markup)**: глобальность — хоткей биндится на
  всё окно, а не на виджет; конфликт с app-биндингами решает
  порядок (markup позже app — или наоборот; зафиксировать в спеке).
- **`ref=`**: `ref` — не структурный атрибут; исключить из
  `seed_props`-пропсов вместе с if/unless/id.
- **Ярус 2 целиком**: каждый пункт сначала проверять на живом порте
  Vue-компонента — «закрывает ли это реальный паттерн», иначе
  получается синтаксис ради синтаксиса.
